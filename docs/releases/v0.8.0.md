# git-rg v0.8.0

Gitee joins GitHub and GitLab as a supported provider for remote search, file reads, draft change proposals, and issue creation.

## English

- Use `gitee:OWNER/REPO`, a Gitee HTTPS clone URL, or an SSH-style clone address. The adapter uses Gitee Open API v5.
- `auto` and `exact` search the pinned snapshot. `refs` lists branches and tags, and `read` returns the full file with its commit and blob SHAs. When the raw-file API returns 401 or 404, the adapter reads and verifies the blob by SHA. Gitee `indexed` returns `indexed_search_unsupported` with exit code 2.
- `propose --dry-run` previews a change plan. With writes enabled, `propose` submits a batch commit on a new branch and verifies the commit before opening a draft PR. `issue create` supports local preview and Agent attribution. Gitee issues use a string `result.identifier`; GitHub and GitLab retain their numeric `result.number` in NDJSON schema v1.
- Writes are off by default. Each write requires `--enable-write` and a `GITRG_WRITE_TOKEN` with the appropriate Gitee scopes. Reads on Gitee.com check `GITRG_TOKEN`, `GITEE_TOKEN`, then `GITRG_WRITE_TOKEN`.

```sh
git-rg --mode exact -F TODO gitee:OWNER/REPO
git-rg refs gitee:OWNER/REPO
git-rg issue create --dry-run --title "Describe the problem" gitee:OWNER/REPO
```

The release ships Linux, macOS, and Windows archives for amd64 and arm64, two installation scripts, and `checksums.txt`. Public Gitee read-only validation covers refs, file reads, search, and proposal previews. The contributor recorded live write checks in [PR #3](https://github.com/SamuelSupe/git-rg/pull/3). Private Gitee installations require validation against their API version.

See [Installation](https://github.com/SamuelSupe/git-rg/blob/v0.8.0/docs/installation.md) and [Gitee usage and API differences](https://github.com/SamuelSupe/git-rg/blob/v0.8.0/docs/gitee.md).

## 中文

- 新增 Gitee Open API v5 适配器。仓库可使用 `gitee:OWNER/REPO`、HTTPS 或 SSH 形式的 clone 地址。
- `auto` 和 `exact` 搜索固定快照。`refs` 列出分支和 tag，`read` 返回完整文件及其 commit 和 blob SHA。raw 接口返回 401 或 404 时，按 SHA 回退读取并校验 blob。Gitee `indexed` 返回 `indexed_search_unsupported`，退出码为 2。
- `propose --dry-run` 可预览变更计划。显式启用写入后，`propose` 在新分支提交一批文件变更并验证提交，再创建草稿 PR。`issue create` 支持本地预览和 Agent 身份。Gitee issue 使用字符串 `result.identifier`，GitHub 和 GitLab 的数字 `result.number` 保持兼容，NDJSON schema 仍为 v1。
- 写入默认关闭。每次写入均需 `--enable-write` 和具备相应权限的 `GITRG_WRITE_TOKEN`。Gitee.com 读取依次检查 `GITRG_TOKEN`、`GITEE_TOKEN` 和 `GITRG_WRITE_TOKEN`。

本版提供 Linux、macOS、Windows 的 amd64 和 arm64 安装包、两个安装脚本及 `checksums.txt`。公开 Gitee 仓库已验证分支列表、文件读取、搜索和提案预览。真实写入的贡献者验证记录见 [PR #3](https://github.com/SamuelSupe/git-rg/pull/3)。自建实例需按实际 API 版本验收。

详见[安装说明](https://github.com/SamuelSupe/git-rg/blob/v0.8.0/docs/installation.md)和 [Gitee 使用与 API 差异](https://github.com/SamuelSupe/git-rg/blob/v0.8.0/docs/gitee.md)。
